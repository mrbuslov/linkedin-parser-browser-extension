              How does this work? — click to expand

              What it does. Paste a list of LinkedIn profile URLs, extension opens each one in a dedicated browser tab, waits for LinkedIn to render the page, humanized-scrolls, waits (reading dwell), then moves on. All captured data (headline, location, company, contact info if present, mutuals) goes into your local contacts store — same as if you'd visited manually.

              Direct /overlay/contact-info/ navigation. Instead of opening a profile then clicking "Contact info", we go straight to the overlay URL. LinkedIn renders both the profile page (behind) and the contact modal (on top) in ONE tab load. Halves the time per profile without any extra requests.

              Why "humanized" matters. LinkedIn's ML detector doesn't just look at request rates — it looks at behaviour: mouse movement, scroll velocity, tab focus patterns, session flow. Naive bots use setTimeout(url_next, 60000) and get restricted in days. Here every timing decision uses distributions that model real reading behaviour:

              • Between-visit pause — exponential distribution, mean 90s. Mostly short, occasionally very long ("stopped to reply to a message").
              • Reading dwell — log-normal, scaled by content volume. Short profile ≈ 30-60s, dense profile ≈ 2-4 min.
              • Scroll plan — variable-velocity scrollBy chunks. Some steps fast, some slow, occasional backward step ("re-read"), occasional pause ("distracted"). Real scroll events, isTrusted=true — LinkedIn sees it as human scrolling.
              • Batch break — after 3 visits, 15-45 min pause. Mimics coffee/lunch break.
              • Feed break — every 5-12 visits, opens /feed/ briefly and scrolls a couple of posts. Real users mix feed browsing into profile viewing; queue-with-zero-feed-visits is a stronger bot signal than any single visit.

              Time-of-day gate. Default window 09:00-21:00 local. Queue sleeps outside and resumes at reopens. Configurable but you can't set an all-night window — it's a hard safety rail. Ночью не работает.

              Warmup mode. First 7 days after starting the first queue: cap = 30% of configured. Prevents a 0→20 spike from tripping LinkedIn's behavioural baseline (accounts that suddenly change activity pattern get flagged).

              Skip rules. Profiles already in your contacts with status='accepted' (1st-degree) get skipped by default — visiting them is wasted quota. Profiles you visited within N days (default 30) also skipped. Both toggleable in Settings.

              What can go wrong. LinkedIn can still restrict your account — no automation is 100% safe. The extension reduces risk, doesn't eliminate it. Signals we watch for:

              • Redirect to /checkpoint/, /uas/, or /error/ during a visit → auto-pause + notification. Complete the check manually then Resume.
              • User activity in the browser (mouse/keyboard) → 5 min deferral so we don't interfere with your work.
              • Contact modal fails to appear within 45s → visit marked failed, queue continues to next.

              What we deliberately don't do.

              • No auto-connect. Sending Connect requests programmatically is what actually gets accounts restricted quickly. This extension never touches Connect buttons.
              • No mouse cursor faking. Browser JS can't move the OS cursor; even if it could, LinkedIn doesn't care about cursor position, only about event trust. We rely on real user-generated events (real scrolls, real navigations).
              • No background-tab visits. Chrome throttles background tabs and hides them from LinkedIn's visibility API — that pattern is easier to detect than an active foreground tab.
              • No parallel visits. One tab, one profile at a time.

              How to control it. Pause / Resume / Cancel buttons are in the popup AND floating on every visit tab (top-right corner). If anything looks wrong — hit Cancel and open the tab manually. Every state is idempotent; nothing breaks from a browser restart or extension reload.

              Recommended use. Warm accounts (used regularly for months), realistic daily caps (start with 10-15 for the first month, then 20), always during your normal activity window. Not for burner/new accounts.

                Recommended for warm accounts (used regularly for months) with realistic daily caps (start with 10-15/day). Not for primary business accounts you can't afford to lose.
